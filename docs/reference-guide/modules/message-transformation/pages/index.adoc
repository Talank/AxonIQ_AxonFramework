= Event Transformation

When an event's stored structure no longer matches what your handlers and projectors expect, an _event transformation_ rewrites it on the way out of the event store.
The stored events stay exactly as they were written; the transformation runs every time those events are read, handing each handler the shape it expects.

A transformation is the tool for the structural changes that xref:events:event-versioning.adoc[payload conversion] cannot express on its own — combining two fields into one, wrapping values in a new object, or lifting a historic event onto a new version.

== When to reach for a transformation

Axon Framework already adapts stored events to the type a handler asks for through its xref:ROOT:conversion.adoc[`Converter`].
Conversion covers most version changes for free: adding fields with defaults, dropping fields a handler no longer reads, renaming fields with Jackson annotations, and changing compatible field types.
Configure your converter first.

Reach for a transformation only when the change cannot be expressed through conversion, for example:

* You need to restructure the payload itself — combine `firstName` and `lastName` into a single `fullName`, or wrap `minCapacity` and `maxCapacity` into a `range` object.
* You want one rule to apply to _every_ handler of an event, rather than adjusting each handler's type or annotations individually.
* You are lifting historic events onto a new version so the rest of your application only ever deals with the current shape.

[TIP]
.Conversion or transformation?
====
A converter changes an event's _representation_; a transformation changes its _structure_.
If a handler can already receive the event by declaring the fields it wants, you do not need a transformation.
See xref:events:event-versioning.adoc[Event versioning] for the conversion-first approach.
====

== What a transformation looks like

A single transformation matches one event identity, declares the identity it produces, and maps the payload from the old shape to the new one:

[source,java]
----
EventTransformer transformer =
        EventTransformation.from(new MessageType("coursecatalog.CoursePublished", "1.0.0"))
                           .to(new MessageType("coursecatalog.CoursePublished", "2.0.0"))
                           .transform(JsonNode.class, CoursePublishedV1ToV2::map);
----

You register one transformer per version step and let Axon Framework apply them in order, so a v1 event read today reaches your handler as the current version.

From here:

* xref:message-transformation:defining-transformations.adoc[] shows how to write the individual transformations, work with generic payloads, and match several event versions at once.
* xref:message-transformation:configuring-transformations.adoc[] shows how to assemble them into a chain, register it, and test it.

== Adding the module

Event transformation ships in the `axoniq-message-transformation` module:

[source,xml]
----
<dependency>
    <groupId>io.axoniq.framework</groupId>
    <artifactId>axoniq-message-transformation</artifactId>
    <version>${axoniq.version}</version>
</dependency>
----

Once the module is on the classpath and an `EventTransformerChain` is registered, Axon Framework applies it automatically whenever events are read from the store.
